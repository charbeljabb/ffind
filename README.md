# ffind

A fast, multi-threaded command-line tool for finding files and folders by name across your whole system. Written in Rust.

```
$ ffind notes ~/projects
/home/you/projects/notes
/home/you/projects/notes/inner/notes
/home/you/projects/a/b/notes
```

## Features

- **Parallel search.** Runs one worker thread per CPU core, all pulling folders from a shared work queue.
- **Searches the whole system by default.** Starts at `/` on Linux and macOS, or `C:\` on Windows.
- **Skips system folders** that waste time and never contain your files, such as `/proc` and `/sys`. You can turn this off with `--bypass-defaults`.
- **Readable output in a terminal.** Matches are colored and a live spinner shows how many folders have been scanned.
- **Script-friendly output.** When piped or redirected, it prints plain full paths, one per line, with no colors or spinner.
- **Single binary.** No runtime or dependencies needed once it's built.

## Installation

You need [Rust](https://rustup.rs) installed.

```bash
git clone <your-repo-url>
cd ffind
cargo install --path .
```

This builds an optimized binary and puts `ffind` on your `PATH`, so you can run it from any folder.

To build without installing:

```bash
cargo build --release
```

The binary will be at `target/release/ffind` (or `target\release\ffind.exe` on Windows).

## Usage

```
ffind [OPTIONS] <TARGET> [PATH]
```

| Argument | Description |
|---|---|
| `<TARGET>` | Text to look for in file and folder names |
| `[PATH]` | Folder to start searching from. Defaults to `/` (Linux, macOS) or `C:\` (Windows) |

| Option | Description |
|---|---|
| `--bypass-defaults` | Also search the folders that are skipped by default |
| `-h`, `--help` | Print help |
| `-V`, `--version` | Print version |

### Examples

```bash
# Search the whole system for names containing "invoice"
ffind invoice

# Search only your home folder
ffind invoice ~

# Find every Rust source file under the current folder
ffind .rs .

# Include /proc, /sys and the other default exclusions
ffind cpu / --bypass-defaults

# Save the results to a file
ffind invoice > results.txt

# Scroll through a long list of results
ffind log / | less

# Count the matches
ffind .jpg ~ | wc -l
```

On Windows, run it from PowerShell or Command Prompt:

```powershell
.\ffind.exe invoice C:\Users
```

## How matching works

- A file or folder matches if its **name contains** `<TARGET>`. Only the name is checked, not the rest of the path.
- Matching is **case-sensitive**: `ffind Notes` won't find `notes.txt`.
- Matching folders are reported, and their contents are still searched.
- Hidden files and folders (names starting with `.`) are included.
- Symbolic links to folders are not followed, so the same files aren't reported twice.
- Folders you don't have permission to read are skipped silently. Run with `sudo` (or as Administrator on Windows) to search them.

## Default exclusions

These folders are skipped unless you pass `--bypass-defaults`. The folder you start the search in is never skipped, so `ffind cpu /proc` still searches `/proc`.

| OS | Skipped folders | Why |
|---|---|---|
| Linux | `/proc`, `/sys`, `/dev`, `/run` | Generated by the kernel on the fly, not real files on disk |
| macOS | `/dev`, `/System/Volumes`, `/Volumes`, `/private/var/vm` | Device files, mirrored volumes that would duplicate every result, other drives, and swap files |
| Windows | `C:\$Recycle.Bin`, `C:\System Volume Information`, `C:\Windows\WinSxS` | Deleted files, restore points, and a very large system component store |

## Output

The output depends on where it's going:

| Destination | What you get |
|---|---|
| A terminal | Folder path dimmed, matching name in bold green, and a spinner showing the folder count |
| A pipe or file (`\|`, `>`) | Plain full paths, one per line |

The spinner is written to stderr, so it never ends up in your saved results.

Results are printed in the order they're found, which varies between runs because several threads search at once. Pipe through `sort` if you need a stable order.

## How it works

`ffind` uses a classic parallel work-queue design:

1. A shared **to-do list** of folders starts with the search root.
2. Each worker thread repeatedly takes a folder off the list, reads its entries, checks each name, and collects any subfolders.
3. New subfolders are added back to the list in one batch, so the shared lock is taken once per folder rather than once per subfolder.
4. A **busy counter** tracks how many workers are currently reading a folder. An empty list only means the search is finished when the counter is also zero, since a busy worker may still add more folders.
5. Idle workers sleep on a **condition variable** and are woken when new folders are added or when the search finishes, instead of repeatedly checking.

Matches for each folder are also collected and written to stdout in a single locked, buffered write, so lines from different threads never interleave.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | The search ran to completion, whether or not anything matched |
| `2` | Invalid or missing arguments |

## Ideas for future work

- Case-insensitive matching (`-i`)
- Exact-name and glob matching, such as `*.pdf`
- Files-only and folders-only filters
- `--exclude <folder>` for custom exclusions
- Stopping early when the output is closed, as with `ffind x | head`
- Exit code `1` when nothing matches, like `grep`
- A saved index for instant repeat searches, like `locate`
